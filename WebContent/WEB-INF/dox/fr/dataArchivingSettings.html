Overview

The Data Archiving module allows you to automatically copy and/or delete old data from selected database tables to an external archival database. This helps reduce the size of the primary database while keeping historical data accessible.

Archiving is configured using flexible rules which define how old the data must be to be archived or deleted, which tables to process, and what action to take (copy or delete). You can also define the destination archive database and how frequently the archiving process runs.

Settings

The configuration consists of the following options:

  • Enable data archiving: Activates or deactivates the archiving mechanism.
  • Archive database URL: JDBC URL of the target archive database (e.g., jdbc:mysql://localhost:3308/scadalts_archive).
  • Archive database username: Username for the archive database.
  • Archive database password: Password for the archive database user.
  • Batch size: Number of records processed in each step during archiving. Helps manage memory and performance.
  • Archive frequency (cron): Cron expression that determines how often the archiving task is run (e.g., 0 0 1 * * ? for daily at 1:00 AM).
  • Archiving Rules: List of individual tasks that define what data should be archived or deleted.

Archiving Rules

Each archiving rule specifies:

  • Older than: How old the data must be to qualify (e.g., 30 days).
  • Action: Whether to Archive (copy to archive DB) or Delete (from main DB if already archived).
  • Table: Which data table to apply the rule to (e.g., pointValues, events).

Usage Example

Archive historical point values older than 30 days to a secondary MySQL database.

  1. Enable the "Enable data archiving" checkbox.
  2. Set the Archive database URL to: jdbc:mysql://localhost:3308/scadalts_archive
  3. Set username and password for the archive database.
  4. Set Batch size to 1000 (default).
  5. Set Archive frequency to 0 0 1 * * ? (every day at 1:00 AM).
  6. In Archiving Rules, add a new rule:
    • Older than: 30 day(s)
    • Action: Archive
    • Table: pointValues
  7. Save configuration.
  8. At 1:00 AM each day, Scada-LTS will move records from pointValues older than 30 days to the archive database.

Additional Notes

  • Ensure that the archive database has the same schema structure as the source tables.
  • The archiving engine will automatically copy table structure if the archive table doesn't exist.
  • Deleted data cannot be recovered unless previously archived.
  • It is recommended to regularly back up both your main and archive databases.
